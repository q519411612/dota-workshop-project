# Plan: Minimal Runtime Ability Proof

**Status:** Ready
**Date:** 2026-07-07

## Implementation Approach

1. Add failing tests for schema parsing, generated ability Lua, KV links, inspect evidence, and smoke marker validation.
2. Extend the unit ability scaffold type and schema with an explicit proof option.
3. Generate a minimal Lua ability marker file only when the proof option is requested.
4. Link ability KV to the generated Lua file and keep existing passive output unchanged by default.
5. Extend marker expectation helpers and smoke validation to include proof markers only when requested.
6. Run targeted tests, build, and repository gates.
7. Record verification, independent review, and summary artifacts.

## Risks

- A generated ability script does not prove runtime execution by itself; only real marker logs can close runtime evidence.
- Smoke validation must not require ability proof markers for existing scaffold users unless the proof option is explicitly requested.
- The implementation must stay minimal and avoid expanding into broader gameplay or UI systems.
