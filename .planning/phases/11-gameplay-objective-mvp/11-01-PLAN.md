# Phase 11 Plan: Gameplay Objective MVP

**Created:** 2026-07-06
**Spec:** `11-SPEC.md`

## Tasks

### 1. Tests First

- Add schema tests for `objective` on `CreateAddonInputSchema` and `RunPlayableSmokeInputSchema`.
- Add addon fixture tests for generated objective Lua markers and invalid objective rejection.
- Add inspect tests for objective configuration and marker evidence.
- Add remote command-construction tests proving objective markers are rendered through shared remote addon creation.
- Add smoke tests proving objective markers are validated when requested and default smoke remains unchanged.
- Run the targeted tests and confirm they fail before implementation.

### 2. Objective Types and Validation

- Add a `GameplayObjective` type for `score` objectives.
- Add `validateGameplayObjective`.
- Keep safe numeric ranges small and explicit.
- Reject objective configuration on the marker-only `minimal` template.

### 3. Lua Rendering

- Extend `renderAddonFiles` and playable Lua rendering to accept optional objective configuration.
- Preserve existing target score and tick interval when no objective is provided.
- Emit objective configured, progress, and complete markers only when objective is present.

### 4. Schema, Server, and Remote Parity

- Add objective input shape to schemas and server registration for `create_addon` and `run_playable_smoke`.
- Pass objective through `createRemoteAddon` and remote command rendering.
- Ensure local and remote paths use the same renderer.

### 5. Smoke Orchestration

- Add `objectiveMarkers(addonName, objective)` helper.
- Expand default expected markers only when `objective` is present.
- Preserve existing placement marker expansion.

### 6. Documentation

- Update README with score objective usage and markers.
- Update skill and references with the objective workflow and deferred complex gameplay systems.
- Update troubleshooting with missing objective marker diagnostics.

### 7. Verification

- Run `git diff --check`.
- Run `npm run typecheck`.
- Run `npm test`.
- Run `npm run build`.
- Run manifest/reference validation.
- Run strict secret scan.
- Run real Windows objective smoke, preferably with `customMap`, and validate objective markers from `game/dota/console.log`.

### 8. Independent Review

- Review source and docs for explicit failure behavior, default compatibility, target parity, and scope drift.
- Fix findings.
- Commit and push.
