# Playable Gameplay Loop MVP Implementation Plan

> **For agentic workers:** REQUIRED: Use TDD for behavior changes. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate and validate a minimal playable Dota 2 custom game loop while preserving the v1.1 runtime marker contract.

**Architecture:** Extend the current TypeScript MCP server without adding new tool names. Keep local and remote paths unified by sharing rendered addon file contents and extending marker validation from one marker to many markers.

**Tech Stack:** TypeScript, Node.js, Vitest, Dota 2 Lua, classic KeyValues addon metadata.

---

## File Structure

- Modify `src/addon.ts`: template selection, playable Lua/KV rendering, inspect evidence.
- Modify `src/schemas.ts`: optional `template` for `create_addon`, optional `expectedMarkers` for `validate_addon`.
- Modify `src/launch.ts`: local multiple-marker validation.
- Modify `src/remote.ts`: remote playable template rendering and multiple-marker validation.
- Modify `tests/addon.test.ts`: TDD coverage for playable template and inspect evidence.
- Modify `tests/local-validation.test.ts`: TDD coverage for multiple gameplay markers.
- Modify `tests/remote-operations.test.ts`: TDD coverage for remote playable generation and marker validation.
- Modify `README.md` and `skills/dota2-workshop-tools/*`: user workflow guidance.
- Add planning summaries/review after verification.
