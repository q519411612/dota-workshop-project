# Plan 01: Release Handoff Bundle Readiness

## Objective

Add a local `verify:handoff` command that emits a structured handoff readiness report, reuses the existing RC verifier, checks delivery artifacts and docs coverage, and records explicit publishing boundaries without performing any real publishing, credential, network, Windows, Steam, Dota, or MCP runtime operation.

## Tasks

### Task 1: Write failing handoff tests

<read_first>
- `tests/rc.test.ts`
- `tests/plugin.test.ts`
- `src/rc.ts`
- `src/plugin.ts`
- `package.json`
- `.planning/phases/01-release-handoff-bundle-readiness/01-SPEC.md`
</read_first>

<action>
Create `tests/handoff.test.ts` with tests for package script exposure, RC preflight aggregation through an injected verifier, missing delivery artifact blockers, documentation coverage blockers, and exact release boundary labels.
</action>

<acceptance_criteria>
- `npm test -- tests/handoff.test.ts` fails because `src/handoff.ts` and `verify:handoff` do not exist yet.
- Tests use temporary fixtures and injected RC results, not real Dota, Steam, network, Windows, SSH, PowerShell, or MCP runtime targets.
</acceptance_criteria>

### Task 2: Implement the handoff verifier

<read_first>
- `src/rc.ts`
- `src/plugin.ts`
- `src/verify-rc.ts`
- `tests/handoff.test.ts`
</read_first>

<action>
Create `src/handoff.ts` with `verifyReleaseHandoff`. It should collect the git commit SHA through an injectable command runner, invoke an injectable RC verifier defaulting to `verifyReleaseCandidate`, build a delivery checklist from repository files, check README/runbook coverage, append explicit boundary entries, aggregate blockers, and return a JSON-serializable report.
</action>

<acceptance_criteria>
- `npm test -- tests/handoff.test.ts` passes.
- Report shape includes `ok`, `commit`, `verification`, `delivery`, `boundaries`, `evidence`, `warnings`, `blockers`, and `paths`.
- Missing required files or docs phrases produce blockers with relative paths.
- Boundary labels include no Workshop upload, Steam login, Steam Guard handling, content encryption, package signing, credential/private target storage, and remote Windows connection.
</acceptance_criteria>

### Task 3: Add the CLI and npm script

<read_first>
- `src/verify-rc.ts`
- `package.json`
- `tsconfig.build.json`
</read_first>

<action>
Create `src/verify-handoff.ts` as the thin CLI entrypoint and add `"verify:handoff": "node ./dist/verify-handoff.js"` to `package.json`.
</action>

<acceptance_criteria>
- `npm run build` creates `dist/verify-handoff.js`.
- `npm run verify:handoff` prints JSON.
- The CLI exits non-zero when blockers exist.
</acceptance_criteria>

### Task 4: Update operator documentation

<read_first>
- `README.md`
- `docs/operator-runbook.md`
- `.planning/REQUIREMENTS.md`
</read_first>

<action>
Document `npm run verify:handoff` in README and the operator runbook. State that it runs after `verify:rc`, is local-only, and does not upload, log into Steam, handle Steam Guard, encrypt content, sign packages, store credentials, or connect to remote Windows.
</action>

<acceptance_criteria>
- README includes the handoff command and local-only boundary text.
- Operator runbook includes the handoff command in local readiness and optional remote smoke ordering.
- Documentation remains free of real credentials, private target values, or private host data.
</acceptance_criteria>
