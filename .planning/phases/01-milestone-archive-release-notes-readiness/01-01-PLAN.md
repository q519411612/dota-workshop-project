# Plan 01: Milestone Archive and Release Notes Readiness

## Objective

Add a local `verify:milestone` command that emits a structured milestone closeout and release notes readiness report, reuses the existing handoff verifier, reports v1.2-v1.7 commit and delivery history, checks README/runbook/handoff coverage, and records explicit publishing boundaries without performing any real publishing, credential, network, Windows, Steam, Dota, or MCP runtime operation.

## Tasks

### Task 1: Write failing milestone tests

<read_first>
- `tests/handoff.test.ts`
- `src/handoff.ts`
- `package.json`
- `.planning/phases/01-milestone-archive-release-notes-readiness/01-SPEC.md`
</read_first>

<action>
Create `tests/milestone.test.ts` with tests for package script exposure, handoff preflight aggregation through an injected verifier, v1.2-v1.7 inventory completeness, documentation coverage blockers, exact release boundary labels, and report path sanitization.
</action>

<acceptance_criteria>

</acceptance_criteria>

### Task 2: Implement the milestone verifier

<read_first>
- `src/handoff.ts`
- `src/rc.ts`
- `tests/milestone.test.ts`
</read_first>

<action>
Create `src/milestone.ts` with `verifyMilestoneCloseout`. It should invoke an injectable handoff verifier defaulting to `verifyReleaseHandoff`, build the fixed v1.2-v1.7 version inventory, validate commit range and inventory completeness, check README/runbook coverage, verify handoff output includes delivery/docs/boundary support, append explicit release boundary entries, aggregate blockers, and return a JSON-serializable report.
</action>

<acceptance_criteria>
- `npm test -- tests/milestone.test.ts` passes.
- Report shape includes `ok`, `milestone`, `commitRange`, `handoff`, `versions`, `documentation`, `boundaries`, `remainingNonBlockingItems`, `evidence`, `warnings`, `blockers`, and `paths`.
- Missing required docs phrases or inventory fields produce blockers with relative paths or version IDs.
- Boundary labels include no Workshop upload, Steam login, Steam Guard handling, content encryption, package signing, credential/private target storage, and remote Windows connection.
</acceptance_criteria>
