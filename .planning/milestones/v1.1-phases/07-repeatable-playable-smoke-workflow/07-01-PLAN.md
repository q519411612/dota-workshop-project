# Repeatable Playable Smoke Workflow Implementation Plan

> **For agentic workers:** REQUIRED: Use TDD for behavior changes. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a repeatable playable smoke MCP workflow that composes addon generation, inspection, runtime launch, and gameplay marker validation.

**Architecture:** Add a small orchestration layer over existing MCP operations. Keep target schema and result shape unified across fixture, local, and remote targets.

**Tech Stack:** TypeScript, Node.js, Vitest, Dota 2 Lua, classic KeyValues addon metadata.

---

## File Structure

- Add `src/smoke.ts`: workflow input, default marker list, addon name generation, orchestration.
- Modify `src/schemas.ts`: `RunPlayableSmokeInputSchema`.
- Modify `src/tools.ts`: route `run_playable_smoke`.
- Modify `src/server.ts`: register the new MCP tool.
- Add or modify tests for fixture/local/remote smoke orchestration.
- Update README and skill references.
- Add Phase 7 summary, verification, and review artifacts.
