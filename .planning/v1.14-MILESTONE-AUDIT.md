# Milestone v1.14 Audit: Workshop Addon Release Candidate Preflight

The milestone cannot be archived yet. All three phase verification reports pass and all 19 requirement IDs have exactly one plan owner and one summary owner, but the independent cross-phase integration audit found two blocking connections that the existing tests do not cover.

## Three-Source Requirement Cross-Reference

- `.planning/REQUIREMENTS.md` contains 19/19 checked requirements and maps each to exactly one phase.
- Phase 3–5 verification reports claim every mapped requirement satisfied with behavioral evidence.
- Phase 3–5 summary frontmatter contains exactly one `requirements-completed` owner for every ID, with no duplicate, orphaned, or extra owner.
- The integration findings above override the affected phase-local claims until remote lifecycle and parity evidence are corrected.

## Cross-Phase Integration

Fifteen expected links are wired, including public schema registration, fixture/local dispatch, exact assembly, shared readiness, final local integrity and cleanup, one-shot SSH/PowerShell execution, strict remote normalization, no fallback, packaged runtime invocation, and source immutability.

Two required links are broken:

1. The generated PowerShell lifecycle hashes each candidate file immediately after copy and later projects the manifest from those stored entries. It rechecks source bytes and topology but never performs the Phase 4 final candidate byte observation before success.
2. The four-target golden test supplies mocked remote stdout by cloning the local normalized payload. Actual generated-script precreation artifact state and warning behavior differ from the asserted contract, so the test does not prove generated lifecycle parity.

## End-to-End Flow Status

Complete flows include fixture success, local adapter success, local fail-closed error paths, remote dispatch and one-shot execution, malformed/uncertain remote evidence rejection, and staged runtime invocation.

Broken flows are SSH success, PowerShell Remoting success, and the four-target golden parity proof. Completion, cleanup, and archival remain gated until all three flows pass after independent re-review.

## Boundary Audit

No prohibited behavior was found. The implementation does not log in to Steam, create or mutate Workshop items, upload, handle credentials, retain candidates or archives, sign, encrypt, compile or repair source, transfer candidate files, launch the game, or claim real Windows evidence. The three user-owned `.planning/graphs/` modifications remain outside audit evidence and commits.

## Required Closure

- Add a fresh final candidate enumeration and byte/hash observation to the generated lifecycle, and project the manifest only from those final facts.
- Align generated remote precreation artifact and warning semantics with the Node contract.
- Replace cloned local remote payloads with an independently derived generated-lifecycle semantic oracle.
- Rerun focused and complete quality gates, independent review, and the milestone audit before completion.
